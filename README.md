# Live Office PPT

Live Office PPT renders JSON slide specs into native PowerPoint decks through the
Windows PowerPoint COM object model. It opens PowerPoint and draws each element
step by step, so the author can watch the deck being built and ask an agent to
adjust the spec immediately.

This project is intentionally not a macro generator and not an SVG-to-PPTX
converter. It keeps text boxes, shapes, connectors, and pictures as editable
PowerPoint objects.

## What It Is Good For

- Technical architecture diagrams
- Research method figures
- Consulting-style process pages
- Data and product narrative slides
- Agent-assisted deck drafting where live visual feedback matters
- Decks that combine native PowerPoint shapes with generated bitmap assets

## Requirements

- Windows
- Desktop Microsoft PowerPoint
- PowerShell 5.1 or newer

The renderer uses local Office automation. It is not designed for headless CI or
Linux servers.

## Quick Start

From the repository root:

```powershell
powershell -ExecutionPolicy Bypass -File .\render-live-ppt.ps1 `
  -Spec .\examples\network-diagram.json `
  -StepDelayMs 80 `
  -Overwrite
```

The example saves a deck under `exports/`.

To validate a spec without opening PowerPoint:

```powershell
powershell -ExecutionPolicy Bypass -File .\render-live-ppt.ps1 `
  -Spec .\examples\network-diagram.json `
  -ValidateOnly
```

To close PowerPoint automatically after saving:

```powershell
powershell -ExecutionPolicy Bypass -File .\render-live-ppt.ps1 `
  -Spec .\examples\network-diagram.json `
  -CloseAfterSave `
  -Overwrite
```

## Image Asset Workflow

Live Office PPT can insert local images with native PowerPoint picture objects.
For agent workflows, use a top-level `assets` list and reference images by ID:

```json
{
  "assets": [
    {
      "id": "hero",
      "type": "image",
      "source": "codex-imagegen",
      "path": "assets/images/hero.png",
      "prompt": "Clean professional product illustration, no text."
    }
  ],
  "slides": [
    {
      "elements": [
        {
          "type": "image",
          "asset": "hero",
          "x": 480,
          "y": 0,
          "w": 480,
          "h": 540,
          "fit": "cover"
        }
      ]
    }
  ]
}
```

The renderer does not call image generation APIs by itself. In Codex or another
agent, generate the image first, copy the selected output into `assets/images/`,
then reference it from the JSON spec.

Supported image fit modes:

- `cover`: crop to fill the frame.
- `contain`: preserve aspect ratio and center inside the frame.
- `stretch`: fill the frame without preserving aspect ratio.
- `original`: keep the image's inserted size.

## Working With Your Own Decks

Generated PowerPoint files are written to `exports/`, which is ignored by Git.
For real work, keep each deck's JSON spec and assets in a separate project
folder, then point `render-live-ppt.ps1` at that spec.

Example:

```powershell
powershell -ExecutionPolicy Bypass -File .\render-live-ppt.ps1 `
  -Spec ..\my-deck-project\deck.json `
  -StepDelayMs 80 `
  -Overwrite
```

Keep reusable templates and sanitized examples in this repository. Keep
client-specific deck specs, private assets, and generated exports in your own
project workspace unless you intentionally want to publish them.

## Limitations

- A normal `.pptx` file will not redraw itself when double-clicked. The live
  drawing effect happens while the external PowerShell script is running.
- Auto-run-on-open would require a `.pptm` macro workflow, which is intentionally
  not the default because Office macro security prompts are disruptive.
- PowerPoint COM behavior can differ slightly across Office versions. Prefer
  validating specs and keeping the renderer conservative.
